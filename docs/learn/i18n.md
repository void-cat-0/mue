# Localized interfaces

[Learn contents][learn-index]

Switch a ferry announcement between English and French on the same text node.

## Start with one namespace

Enable `features = ["i18n"]` on your `mue` dependency. Put messages for a screen in a namespace, such as `harbor`. This example passes FTL strings inline. In a larger app, pass the contents of bundled `.ftl` files with `include_str!`.

<div class="mue-demo">
<div class="mue-demo-code">

```rust,no_run
# #[cfg(feature = "i18n")]
# fn demo() -> Result<(), Box<dyn std::error::Error>> {
use mue::{i18n::{CatalogBuilder, I18n, langid}, prelude::*};

let mut catalog = CatalogBuilder::new();
catalog.add_ftl(langid!("en-US"), "harbor", "status = Ferry boarding")?;
catalog.add_ftl(langid!("fr"), "harbor", "status = Embarquement")?;

let i18n = I18n::new(catalog.build()?, langid!("en-US"))?;
let harbor = i18n.translator("harbor")?;
let owner = OwnedScope::new();
let view = owner.run(|| {
    text(harbor.text("status"))
        .style(style! { font-size: 26px; color: #183c2e; })
});

// After displaying the first frame, switch languages.
i18n.set_locale(langid!("fr"))?;
# Ok(())
# }
# #[cfg(feature = "i18n")]
# demo().unwrap();
```

Build an `App` with `view` and call `set_locale` after the first frame. Keep `owner` and `i18n` alive while the node uses the translated text. `harbor.text(...)` allocates the binding in the current scope. Use a component body or `owner.run(...)` to give it an owner.

## Pass reactive arguments

Add a boarding gate to the English and French resources. Keep the key identical in both bundles. The number can come from a signal.

```ftl
# en-US
berth = Berth { $number }
# fr
berth = Quai { $number }
```

After mounting, change the signal from 2 to 3. The existing text binding uses the active locale and the current number.

```rust,no_run
# #[cfg(feature = "i18n")]
# fn berth_label(harbor: mue::i18n::Translator, berth: mue::prelude::Signal<u32>) {
use mue::{i18n::tl, prelude::*};

let _label = text(tl!(harbor, "berth", "number" => berth.get()));
# }
```

`tl!` calls `text` or `text_with`. Write argument providers that read existing values and return owned arguments. Keep numbers numeric so Fluent can apply plural rules.

## Let Fluent choose the plural form

Add this message to the English resource in the first example. The select expression chooses a variant from the numeric argument.

```ftl
checks = { $count ->
    [one] One open check
   *[other] { $count } open checks
}
```

Replace the single announcement with this view. Press **Resolve one** and watch the same label change from `2 open checks` to `One open check` and then `0 open checks`.

```rust,no_run
# #[cfg(feature = "i18n")]
# fn plural(harbor: mue::i18n::Translator) {
use mue::{i18n::tl, prelude::*};

let checks = signal(2_u32);
let view = vstack().gap(8.).children((
    text(tl!(harbor, "checks", "count" => checks.get())),
    button("Resolve one").on_activate(move || {
        checks.update(|count| *count = count.saturating_sub(1));
    }),
));
# }
```

Write the plural variants required by each language in its own resource. Keep `checks.get()` inside the argument expression so the label follows future updates.

## Choose a translation API

| Use | Method |
| --- | --- |
| A one-time string and its diagnostics | `format` |
| Text that follows the locale | `text` |
| Text that also follows reactive arguments | `text_with` or `tl!` |
| A live result with locale and diagnostic details | `bind` |

Each namespace needs an `en-US` resource. You choose the starting locale. If a translation is missing in that locale, Mue looks in the English bundle. Use `format` or `bind` to inspect the resolved locale and formatting issues. Duplicate IDs within one language and namespace fail catalog construction. Try removing `berth` from the French resource. The status remains in French and just the missing berth message uses English. See [catalogs, bindings, and fallback][i18n-reference] for message attributes, locale ownership, diagnostics, and Fluent number formatting.
